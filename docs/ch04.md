# 第4章 一切皆插件

> **阅读提示**
> 本章讲 dsh 的立身之本：插件机制。读完你会明白"一切皆插件"到底彻底在哪，以及为什么这个设计让 dsh 可以被随意改装。地基是 [Cordis](https://github.com/cordiverse/cordis) 框架，我们只讲它的大白话版本。

## 想换个零件，不用拆车

先立个靶子。假设你想给 AI 助手换个大脑供应商——不用 DeepSeek 了，换别家模型。

多数产品的做法：改核心代码、重新编译、重新发版。你作为用户，门都没有。

dsh 的做法：**模型适配器只是一个插件**。拔掉旧的，插上新的，完事。工具、界面、审批策略、甚至"司机"（agent loop），全是同等待遇。

这背后是一套叫 Cordis 的插件框架。它的设计论文题目很长（[《一种时空可组合的编程范式》](https://github.com/cordiverse/paper)），但核心思想用一家公司就能讲清。

## Context：共享总部

Cordis 的世界里有一个共享总部，叫 **Context**（代码里缩写 `ctx`）。

插件就像来入职的员工：入职时在总部办三件事（图4-1 左半）：

![插件的挂载与卸载](images/fig4-1-plugin-lifecycle.svg)

**图4-1 插件的挂载与卸载**

**表4-1 Cordis 术语翻译表**

| 术语 | 大白话 | 类比 |
|---|---|---|
| Context (ctx) | 共享总部 | 公司办公楼 |
| Plugin | 入职的员工 | 干活的单位 |
| Service | 挂在总部的服务台 | 带名牌的前台 |
| Event | 总部广播 | 公司群消息 |
| Effect | 登记在册的操作 | 入职/离职台账 |

## Service：带名牌的前台

服务台按名字挂在总部上。想找谁办事，直接报名字，不用管台子后面坐的是谁：

**表4-2 几个真实的服务台（第3章见过）**

| 名字 | 管什么 |
|---|---|
| `ctx.sessions` | 会话日志（会议纪要） |
| `ctx.tools` | 工具登记与执行 |
| `ctx.llm` | 大脑连接（模型适配） |
| `ctx.agents` | agent 接待口 |

第 3 章那句"只认前台、不认司机"说的就是这个：所有插件只找 `ctx.agents` 办事，不关心具体哪个 agent-loop 在开车。前台后面换人，全公司照常运转。

## Event：总部广播

广播机制：有人发消息，所有订阅了这个频道的人都收到。dsh 有三个主要频道（第 5 章展开）：

| 频道 | 播什么 |
|---|---|
| 会话事件 | 账本上新的一页（永久记录） |
| `agent/*` | agent 的实时动态（正在想什么、干什么） |
| 能力事件（`fs/*` `tools/*`） | 谁想给某项能力加规则，在这里挂 |

其中一种特殊广播叫 **waterfall（瀑布）**：消息沿着一排负责人依次传递，每人都可以说"到我为止"或"继续往下"。审批流就是它——第 6 章的主角。

## 可逆性：dsh 最硬的规矩

Cordis 有条铁律：**插件挂载时做的每件事，都必须能原样撤销。**

前台要能撤、群要能退、台账要能销。员工离职（卸载）之后，总部恢复原状，像这个人从没来过（图4-1 右半）。

这条规矩带来一个了不起的能力：**热换件**。

> 现实里换轮胎要停车；dsh 可以边开边换。

官方示例 [web-cordis](https://github.com/deepseek-ai/deepseek-harness/tree/master/examples/web-cordis) 演示了最极端的一招：让 agent **检查并修改自己体内的插件树**——自己给自己做手术，还不出事。靠的就是"每一步都能回滚"。

为什么对 AI agent 尤其重要？因为 dsh 允许模型现场写插件、挂插件（后面章节会见到）。模型写的东西随时可能是错的——**错了必须能一键撤销**，这是设计底线。

## "一切皆插件"有多彻底

看清单就知道（表4-3）：

**表4-3 dsh 里哪些东西是插件**

| 部件 | 是插件吗 | 意味着什么 |
|---|---|---|
| 模型适配器 | ✅ | 大脑可以换供应商 |
| 工具注册表 | ✅ | 工具集可以整套替换 |
| 会话日志 | ✅ | 记账方式可以换 |
| agent loop（司机） | ✅ | 驾驶逻辑可以换 |
| Web 界面 | ✅ | 界面可以不要，也可以换 |
| 沙箱、审批策略 | ✅ | 安全策略可配置 |

**没有特权内核。** 不存在"这块神圣不可侵犯、只能打补丁"的地方——想扩展，就把自己的插件挂载到别人的插件旁边，大家地位平等。

## Profile 组装：三明治叠层法

那一次启动时，这么多插件怎么拼到一起？答案是**按层叠加**，像叠三明治（图4-2）：

![Profile 的三明治叠层](images/fig4-2-sandwich-layers.svg)

**图4-2 配置树的叠层组装**

从空桌子开始，一层一层往上叠：先叠 profile 列出的组合包（比如 `dsh-base` → `dsh-web-app`），再叠 profile 自己的覆盖文件，再叠你家（`$DSH_HOME`）的覆盖文件，最后叠启动时 `--patch` 指定的那层。

每一层都是一份"修改单"（patch）：按编号找到某道菜，整道换掉，或者添一道新菜。**后叠的层永远说了算。**

想看自己的车到底装了些什么？不用启动，一条命令打印完整配置树：

```sh
dsh --profile web --dump-config
```

打印出的任何一项，你都可以写自己的 patch 把它换掉。这就是改装的入口——第 12 章的主题。

## 📝 小结

- **Context 是共享总部**——插件在上面登记服务、订阅广播、留下操作记录
- **服务台按名字找人**——`ctx.tools`、`ctx.llm` 等，换人不影响办事
- **可逆性是铁律**——卸载即回滚，所以能热换件，agent 甚至能给自己做手术
- **没有特权内核**——模型、工具、日志、司机、界面，全是平级插件
- **组装靠三明治叠层**——bundle → 各级 patch，后叠的说了算；`--dump-config` 可自查
