# 第11章 你的第一个插件

> **阅读提示**
> 前面十章都在拆别人的零件，这一章你自己造一个。放心，最小的插件只有几行；就算不亲手写，看懂这一章也能明白社区插件都在干什么。

## 一个插件的最小形态

Cordis 插件最小的样子，就是一个文件里一个函数：

```ts
export function apply(ctx) {
  console.log('hello from my first plugin')
}
```

翻译成人话：

- `apply` 是"入职手续"——插件被挂载时，框架调用它
- `ctx` 就是第 4 章那个共享总部——你在里面登记服务、订阅广播
- 函数体里干的事，就是这个插件的全部贡献

就这么几行，已经是一个合法插件了。

插件一共有三种形态（表11-1），新手只需要认识第一种：

**表11-1 插件的三种形态**

| 形态 | 长什么样 | 什么时候用 |
|---|---|---|
| 函数 | 一个 `apply` 函数 | 绝大多数场景，起步就用它 |
| 对象 | 带 `apply` 方法的对象 | 需要挂点元数据时 |
| 类 | 继承 Service 的类 | 要对外提供正式服务时（第 3 课讲） |

## 装配清单：cordis.yml

插件写好了，怎么让应用加载它？答案是一份装配清单：

```yaml
- name: './hello.ts'
```

框架启动时读这份清单，把列出来的模块一个个挂载。官方的 `dsh-base` 组合包，本质就是一份**更长的同款清单**——你终于知道第 2 章下载的"配方"里面是什么了。

两个反直觉但重要的细节：

- **清单顺序 ≠ 加载顺序**。插件们并发启动，谁先谁后由服务依赖决定，不由文件里的位置决定
- **加载失败会明确报错**，不会静默跳过。又是那个原则：让失败显形

## 不自己写：装别人的插件

更多时候你是"装零件"而不是"造零件"。两条路：

- **命令行安装**：`dsh plugin --profile <名字> add <包名>`，把社区插件装进某个 profile
- **挑现成的**：GitHub 上给仓库打 [`dsh-plugin` 话题](https://github.com/topics/dsh-plugin)就能被发现，社区已有不少 awesome 清单

装插件就是往装配清单里加一行。卸载就是把那行去掉——第 4 章的可逆性保证了：**拔下来的时候，一切恢复原状**。

## 🧪 本章实验

> **实验 11-1 ★★｜跑通 hello 插件**
> 目标：亲眼看到自己的插件被挂载。
> 步骤：clone 官方仓库，跟着 [cordis 教程第 1 课](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-tutorial/01-first-plugin.zh.md)做一遍 hello.ts + cordis.yml。
> 验收：终端打印出 `hello from my first plugin`。

> **实验 11-2 ★｜故意让它失败**
> 目标：验证"失败显形"。
> 步骤：照着教程把 `apply` 改成抛异常，再跑一次。
> 验收：进程明确报错退出，而不是假装没这个插件。

## 📝 小结

- **最小插件 = 一个 apply 函数**，拿到 ctx 就能登记贡献
- **三种形态**——函数起步，类留给正式服务
- **cordis.yml 是装配清单**——顺序由依赖定，失败必显形
- **五张官方菜谱**——加工具是最直观的下手处
- **装别人的插件**：`dsh plugin add`，卸载即回滚
