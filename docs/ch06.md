# 第6章 工具执行流水线

> **阅读提示**
> 模型说"我要执行一条命令"，到命令真的跑起来，中间隔着一条流水线。这一章拆流水线上的每道关卡——它们是 agent 安全的最后一道防线。

## 模型从不亲自动手

复习第 1 章的分界线：大脑只负责**申请**用工具，真正动手的永远是身体。

身体在动手之前，会让这次调用先过一条流水线（图6-1）。官方给这条流水线画过一张详图（[原文](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-execution-pipeline.zh.md)），本书把它简化成人话版：

## 动手之前，先记账

流水线第一步不是执行，而是**记账**：`tool/call` 事件先写进会话日志，然后才轮到关卡。

哪怕这次调用最后被拒绝、什么都没干，日志里也有它"申请过"的记录。和第 5 章的"被拒绝的轮次也留痕"一个道理：**尝试过就要有迹可循**。

## 关卡①：pre-execute

第一道关卡是瀑布式的（第 5 章讲过"传令"机制），三类负责人依次过手：

| 负责人 | 管什么 |
|---|---|
| 钩子（hooks） | 外部系统挂进来的检查逻辑 |
| 权限策略 | 这类操作在当前预设下许不许 |
| 沙箱策略 | 在受限环境里能不能跑 |

裁决只有三种（表6-1）：

**表6-1 三种裁决**

| 裁决 | 后果 |
|---|---|
| 放行 | 进入下一关 |
| 拒绝 | 跳过工具本体，直接去关卡③ |
| 要审批 | 弹一次窗问你 |

审批有个重要的保守设计：**没人能回答时，按拒绝处理**。你不在电脑前、弹窗超时、环境没法交互——一律不干。宁可不干，不可乱干。

## 关卡②：单调守卫

第二道关卡叫"单调守卫"。"单调"的意思是：**不能绕过、不能重新排序**。

权限策略可以商量（关卡①可以配），但守卫注册的是铁规矩——比如官方的 [guard 包](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/guard)干的两件事：

- 发现模型在**重复调用**同一个工具，给出提醒（防打转）
- 给执行强制**截止时间**（防卡死）

这些规矩不参与"商量"，只在流水线里固定位置生效。

## 执行本体：包着跑

过了关卡，才轮到工具真正执行。但执行也被一层包装罩着，管三件事：**超时、重试、计时**。

工具本体出了任何错（包括抛异常），都会被流水线**规范成一个错误结果**——不会把整个对话循环搞崩。模型看到的是"这一步失败了，原因是……"，然后它自己决定下一步。

碰文件的操作还有一道专属小关卡：**先看过，才许改**。没读过的文件不许直接编辑——防止模型凭想象改代码。

## 关卡③：post-execute

结果出来后，还要过第三道瀑布关卡。这里能做的事比"看一眼"多（表6-2）：

**表6-2 post-execute 的四种动作**

| 动作 | 大白话 |
|---|---|
| 接收 | 原样放行 |
| 拦截 | 这次结果不给模型看 |
| 替换 | 换一个结果给模型（比如脱敏） |
| 补上下文 | 在结果后面附加说明 |

## 冻结与记账

过了三关，结果被**冻结**——不可再改，然后：

1. `tool/result` 事件写入日志——这是模型能看到的**唯一**结果版本
2. UI 上显示完成卡片
3. 同批的其他工具调用也都结算后，循环决定要不要开下一个步骤（回到第 5 章的图5-2）

注意"唯一版本"：日志里的、模型看到的、界面显示的，是同一个冻结结果。没有"模型看到一个版本、日志记另一个版本"的空间。

## 🧪 本章实验

> **实验 6-1 ★｜触发一次审批**
> 目标：亲眼看关卡①的弹窗。
> 步骤：Web UI 里让 agent 干一件权限策略要求审批的事（比如删除一个测试文件）。
> 验收：弹出审批询问；你点拒绝后，agent 会告诉你"被拒了"而不是硬来。

> **实验 6-2 ★★｜在账本里找到流水线痕迹**
> 目标：把图6-1 和真日志对上。
> 步骤：做完实验 6-1 后，打开该会话的日志文件。
> 验收：能找到 tool/call 和 tool/result 事件，且被拒的调用也有 tool/call 记录。

## 🤔 思考题

1. ★ 为什么"没人回答审批"要按拒绝处理，而不是先干了再说？
2. ★ 关卡③能"替换结果"——想一个正当用途。（提示：敏感信息）
3. ★★ 如果让模型直接执行命令、跳过整条流水线，最先出的事会是什么？

## 📝 小结

- **动手前先记账**——`tool/call` 先落日志，被拒也留痕
- **关卡①**——钩子/权限/沙箱，裁决三选一；审批没人答 = 拒绝
- **关卡②**——单调守卫，铁规矩不可绕过（防重复、防卡死）
- **执行带包装**——超时/重试/计时，异常规范成错误结果
- **关卡③**——结果可被接收/拦截/替换/补充，然后冻结、记 `tool/result`
