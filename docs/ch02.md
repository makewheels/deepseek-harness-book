# 第2章 5 分钟跑起来

> **阅读提示**
> 本章在你自己电脑上把 dsh 跑起来，并完成第一次真实对话。一切顺利的话 5 分钟；要装 Node.js 的话再加 5 分钟。

## 一行命令的安装

看到别人演示 AI 编程助手，你心想：这玩意儿我也想在电脑上跑一个。

用 dsh 的话，"安装"就是一行命令：

```sh
npx @deepseek-ai/dsh web
```

这一行在幕后干了三件事（图2-1）：

![一行命令做的三件事](images/fig2-1-install-flow.svg)

**图2-1 一行命令做的三件事**

前提只有一个：Node.js（仓库要求 **22.19+ 或 24+**），去 [nodejs.org](https://nodejs.org/) 装即可。

首次运行要走网络下载，耐心等。看到终端打印下面这行，就是起来了：

```text
dsh web: http://127.0.0.1:3080
```

这个服务会一直运行，占着这个终端窗口。

## 你下载的其实是"零件 + 配方"

容易误会 dsh 是"一个程序"。实际上下载的是一箱乐高零件，加一份官方装配配方——配方名叫 **profile**。

![web profile 的叠层](images/fig2-2-profile-layers.svg)

**图2-2 web profile 的叠层**

配方和零件都存在你电脑上的 dsh 之家（环境变量叫 `$DSH_HOME`）里。以后你想改装这辆车，改的就是这里——第 12 章细讲。

日常最常用的四条命令（表2-1）：

**表2-1 常用命令速查**

| 命令 | 干什么 |
|---|---|
| `dsh web` | 启动网页界面（`--profile web` 的别名） |
| `dsh --profile headless "任务"` | 无界面干完一件事，打印答案后退出 |
| `dsh --profile web --port 8080` | 换个端口（应用参数写在启动参数后面） |
| `dsh --profile web --dump-config` | 不启动，只打印当前配置树 |

## 打开浏览器后的三步

全新的 dsh 像一辆没钥匙、没车库的车。打开 `http://127.0.0.1:3080` 后按顺序做三件事（图2-3）：

![首次使用四步](images/fig2-3-first-run-steps.svg)

**图2-3 首次使用四步**

**① 拿钥匙。** 去 [DeepSeek 开放平台](https://platform.deepseek.com/) 注册并创建 API key。

> **注意**
> dsh 没有订阅制，全靠 API key 按量计费——**不会有任何东西在你花超之前叫停你**。日常使用很便宜（简单任务几分钱一次），但价格以[官方页面](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)为准。

**② 插钥匙。** 打开 **设置 → 模型**，粘贴 API key 保存。模型路由立即可用，不用重启。

**③ 选车库。** dsh 启动时所在的目录，是它的默认文件系统位置；全新界面还要手动**添加并选中一个工作区**——选中之前，输入框是灰的。

为什么非要选工作区？这是刻意的安全设计：身体只在你圈定的地盘里活动。第 9 章讲沙箱时还会再见这个思路。

## 第一次真实对话

官方指南建议的开场白：

> Summarize this repository and identify its main packages.
> （总结这个仓库，找出它的主要包。）

然后看着它干活：agent 会自己读文件、跑命令。如果某个动作按权限策略需要审批，界面会先弹窗问你——那是"规矩"器官在工作（第 6 章细讲）。

## 另一种形态：无头模式

不想开网页的话：

```sh
npx @deepseek-ai/dsh --profile headless "把这个目录里的 markdown 笔记整理出一份目录"
```

它自己干完，打印最终答案，进程退出。适合写进脚本做自动化——第 12 章组装自己的 agent 时还会用到。

## 🧪 本章实验

> **实验 2-1 ★｜装起来**
> 目标：看到 dsh 的网页界面。
> 步骤：终端运行 `npx @deepseek-ai/dsh web`，等打印出地址，浏览器打开。
> 验收：看到 dsh 界面，终端里服务还在运行。

> **实验 2-2 ★★｜第一次对话**
> 目标：让 agent 真的读一次你的文件。
> 步骤：填好 API key、选中一个有内容的文件夹当工作区，发送官方开场白。
> 验收：agent 给出了基于真实文件的总结；留意中途弹出的审批弹窗（如果有）。

> **实验 2-3 ★★｜使唤一次无头模式**
> 目标：体验"一条命令干完一件事"。
> 步骤：对一个笔记目录运行上面的 headless 命令。
> 验收：终端打印最终答案，进程自己退出。

## 🤔 思考题

1. ★ 为什么 dsh 要先选工作区才让你说话？如果默认全盘可动会怎样？
2. ★ "没有订阅、纯按量计费"对尝鲜者是好处还是风险？
3. ★★ 想在一台机器上同时跑两个互不干扰的 dsh，你会改端口还是改 home 目录？（提示：`--port` 和 `$DSH_HOME`）

## 📝 小结

- **安装一行命令**——`npx @deepseek-ai/dsh web`，需要 Node.js 22.19+ 或 24+
- **下载的是零件 + 配方**——profile 是组合包的叠层，存在 `$DSH_HOME`
- **首次三步**——填 API key → 选工作区 → 开始对话
- **审批弹窗**是"规矩"器官在干活
- **headless 形态**——一条命令一件事，适合自动化
