    第12章 组装自己的 agent¶

    阅读提示 零件会造了，这一章学装车。三条路线由轻到重：改配置、换配方、按会话装不同的 agent。结尾认识六台官方样机车。

    Profile：一辆车的全部档案¶

    回顾第 2 章：profile 是配方，存在 $DSH_HOME/profiles/<名字>/ 下。每个 profile 目录里有三样东西（表12-1）：

    表12-1 profile 目录里有什么

    文件 作用
    dsh.profile（清单） 这辆车叠哪些 bundle，按什么顺序
    cordis.patch.yml 你自己的改装层（按 id 换条目、加条目）
    package.json 装了哪些树外插件（dsh plugin add 的产物）

    启动时的叠层顺序，图4-2 讲过：bundle 们按清单顺序叠 → 你的 patch → 你家的 home 级 patch → 启动时 --patch 临时层。后叠的说了算。

    官方的 web 和 headless 两个模板，第一次用会自动初始化。想从零拼，就用 dsh plugin 创建自己的 profile。

    改装三部曲¶

    图12-1 改装三部曲

    路线一：轻改装。 在自己的 cordis.patch.yml 里按 id 找到某个条目，整条换掉。比如把默认的工具集换成精简版、把审批策略调严。几行配置的事。

    路线二：新配方。 建一个新 profile，选不同的 bundle 组合。dsh-base 是每辆车都要的地基（模型适配、工具、沙箱、审批、设置、凭据），往上你可以只叠 dsh-headless（纯命令行干活，不带服务器），也可以叠自己的 bundle。

    路线三：preset。 同一辆车，不同的会话装出不同的 agent。preset 用一份 cordis.yml 按会话组装能力组合——有的会话要全套工具，有的会话只要最小集。这是官方"一套底盘、多种车型"的玩法。

    随时可以验货：--dump-config 打印最终配置树；--patch 再临时加一层覆盖，不动原车。

    六台官方样机车¶

    官方 examples 目录停了六台样机车，每台演示一种接法（表12-2）：

    表12-2 六台样机车

    样例 演示什么
    headless-agent 无界面干活：给任务、出结果、退出
    jsonrpc-agent 用 Python SDK + JSON-RPC 遥控编码 agent
    acp-agent 面向程序化客户端的自动化服务器（会话/权限/取消）
    web-cordis 让 agent 检查并修改自己体内的插件树（自己给自己做手术）
    web-schedule 给 Web 版加会话内定时提醒的 overlay
    mcp-memory 接第三方记忆服务器的 overlay

    特别值得看的是 web-schedule：它的启动方式就是第 12 章概念的活教材——

    dsh web --patch examples/web-schedule/cordis.yml

    一行 --patch，给现成的 web 车临时加装一套提醒功能，不改任何原有文件。

    出厂之后：三种交付姿态¶

    车造好了怎么给别人用？三种姿态（表12-3）：

    表12-3 三种交付姿态

    姿态 零件 适合
    进程外遥控 sdk（JSON-RPC 协议 + 客户端） 自己的程序里嵌一个 agent
    自动化服务 acp（Agent Client Protocol 服务器） 给别的自动化系统当后端
    与邻居互通 hooks（兼容 Claude Code / Codex 的线协议） 借用别家生态的钩子

    🧪 本章实验¶

    实验 12-1 ★｜验一次货 目标：看懂自己的配置树。 步骤：运行 npx @deepseek-ai/dsh --profile web --dump-config。 验收：能指出三个条目分别属于哪个 bundle 叠进来的。

    实验 12-2 ★★｜给 web 车加装提醒 目标：体验 --patch overlay。 步骤：clone 官方仓库，运行 dsh web --patch examples/web-schedule/cordis.yml，在会话里用 schedule 工具设一个提醒。 验收：到点后提醒出现；去掉 --patch 重启，功能消失——原车毫发无损。

    🤔 思考题¶

    1. ★ 为什么"后叠的层说了算"这个规则，让多人协作改装不容易打架？
    2. ★ preset 让同一辆车按会话变车型——想想这比"每种需求部署一套"省了什么。
    3. ★★ web-cordis 让 agent 改自己的插件树，第 4 章说靠"可回滚"保命。还需要什么配套才敢真用？

    📝 小结¶

    • profile = 一辆车的全部档案——清单、改装层、树外插件
    • 改装三部曲——patch 换条目 → 新 profile 换组合 → preset 按会话装车型
    • 验货工具——--dump-config 看成品，--patch 临时加层
    • 六台样机车——从无头到自我修改，各有各的接法
    • 三种交付姿态——SDK 遥控、ACP 服务、hooks 互通
